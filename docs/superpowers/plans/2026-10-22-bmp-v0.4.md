# mrt v0.4 (BMP reader) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Read BMP v3, from a byte stream and from Kafka frames wrapped in OpenBMP, and yield `mrt.Route`s with MRT semantics. ADD-PATH comes from Peer Up, per family and direction, and AS width from the A flag.

**Architecture:**
- `bgp` gains `FamilySet` and `Context.AddPathFamilies` (ADD-PATH per family), `ParseOpen` with capabilities 1, 65 and 69, `AddPathFamilies` negotiation, and `ParseNotification`.
- `mrt.Route` and `mrt.Peer` gain BMP fields, zero on MRT routes, plus `View`, `PeerType` and `KindEndOfRIB`.
- A new package `bmp` frames and decodes messages and turns them into routes through a per-router `Session`.
- `bmp/openbmp` reads the binary OBMP v1.7 envelope.
- The oracles: a Rust harness over bgpkit-parser 0.22.0's library, and gobgp v4.10.0's bmp package in `internal/compare`.

**Tech Stack:** Go 1.23 floor, standard library only, `net/netip`, `iter`. The oracle harness is Rust (cargo) and gobgp is in the nested `internal/compare` module.

**Spec:** `docs/superpowers/specs/2026-10-22-bmp-design.md`. Approved 2026-10-22, with the user's rulings at its head. Read it with this plan; CLAUDE.md is the operating contract.

## Global Constraints

- Branch `release-0.4.0` (exists; the spec is its first commit). Commit only on it. Pushing, PRs, merging, tagging and releasing wait for the user's explicit go-ahead.
- Root `go.mod`: `go 1.23`, no `require`. `go list -deps ./... | grep -x net` prints nothing. `net/netip` only.
- AS width from the A flag (types 0-2) or 4-byte for Loc-RIB, never from the bytes. ADD-PATH from Peer Up only, never inferred from whether NLRI parse.
- Import direction `cmd → bmp/openbmp, bmp → mrt → bgp`. `bgp` imports neither `mrt` nor `bmp`, and `openbmp` imports nothing from `bmp`.
- C1-C3 hold (`go run ./internal/apisurface -check`). After an API change, `MRT_API_UPDATE=1 go run ./internal/apisurface -check`, then read `git diff api/`. The new goldens are `api/bmp.txt` and `api/bmp_openbmp.txt`.
- **Nothing changes for MRT callers.** `mrt.Routes` and `mrt.RoutesWith` yield exactly what they yield in v0.3.2; every existing golden, `TestLossless` and the interner tests pass with no re-recording.
- A golden is oracle output, never hand-edited (`MRT_GOLDEN_UPDATE=1`, then read `git diff testdata/golden`).
- **No contact with any Kafka broker**, topic listing included (user, 2026-10-22). The capture script and real-data test are written, not run.
- Every figure in a doc or the CHANGELOG comes from a command run in this work, with its log under `.data/` named; otherwise it is "unknown".
- Heavy runs (benchmarks, `internal/compare`) go one at a time, alone, under `memguard.sh` (or `GOMEMLIMIT` plus a watchdog if memguard is missing).
- Before "done": `memguard.sh 8 3600 env GOMAXPROCS=4 FUZZTIME=15s scripts/check.sh`, output to a file, then `echo "exit=$?"`. It ends `SUCCESS` and `check: ok`. routecheck builds and passes against the branch in a scratch copy, and an independent reviewer reads the whole diff.

## Review Focus

1. **A Kafka consumer reuses its frame buffer after `ParseMessage`.** Routes decoded through an `Interner` must be unchanged afterwards. Without one, the docs must say paths alias the frame, as MRT's do. Test in Task 7: `TestSessionInternerSurvivesBufferReuse`.
2. **A frame still wrapped in OpenBMP is passed to `bmp.ParseMessage`.** Expect an `ErrMalformed` whose text says it is an OpenBMP frame and names `openbmp.Parse`, never a generic version error. Test in Task 4: `TestParseMessageOpenBMPFrame`.
3. **A capture that starts mid-message, or has garbage between messages.** Expect errors and no hang. Memory stays bounded, every input byte is accounted for, and lossless still holds. Test in Task 5: `TestMessagesGarbagePrefix`.
4. **An IPv6 peer (V flag) announcing IPv4 NLRI, and the reverse.** The route family comes from the NLRI, never from the V flag. Test in Task 7: `TestSessionFamilyNotFromVFlag`.
5. **End-of-RIB, or an empty UPDATE, before any Peer Up.** No `bmp/addpath-unknown` diagnostic and no error; with `EndOfRIB`, one `KindEndOfRIB` route. Test in Task 7: `TestSessionEndOfRIBBeforePeerUp`.
