# mrt v0.1.0: streaming MRT reader and BGP UPDATE decoder — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A new, dependency-free Go module `github.com/rkolesnichenko/mrt` that streams every MRT record type RIS and RouteViews write today, decodes BGP UPDATEs, yields routes, and is held byte for byte to bgpdump and field by field to bgpkit-parser.

**Architecture:** Package `bgp` decodes BGP messages and path attributes under an explicit `Context` (AS width, add-path, MRT RIB). Package `mrt` frames records from an `io.Reader`, decodes only each record's fixed fields, and leaves RIB entries and attributes to lazy accessors; `Routes` joins records into one route per (peer, prefix, path ID). `cmd/mrtdump` prints bgpdump's `-m` format and is the differential's subject.

**Tech Stack:** Go 1.23 floor, standard library only (`compress/gzip`, `compress/bzip2`, `net/netip`, `iter`); oracles bgpdump (RIPE-NCC/bgpdump master @ `caf2cb07bc3cf06f1720c4cb274811599e9bda6a`, code identical to 2023-11-05) and bgpkit-parser v0.22.0 (2026-09-10).

**Spec:** `docs/superpowers/specs/2026-10-16-mrt-design.md` (approved 2026-10-16). Read it first; this plan argues from it. Section numbers below (§4.1 …) are the spec's.

## Global Constraints

- Module path `github.com/rkolesnichenko/mrt`; `go 1.23` in `go.mod`; **no `require` lines** in the root `go.mod`, ever. `internal/compare` is a nested module with its own `go.mod` (it may require gobgp).
- No dependency on any `github.com/rkolesnichenko/rpsl` module. ASNs are `bgp.ASN` (`uint32`).
- Import direction `cmd → mrt → bgp`; `bgp` never imports `mrt`. No package imports `net` (check: `go list -deps ./... | grep -x net` prints nothing).
- `net/netip` only; no `net.IP`/`net.IPNet`.
- Conventions C1–C3 (spec §3): `X`/`XWith(…, XOptions)`; whole-value parsers return `(T, []Diagnostic)`, single values `(T, error)`; sentinels `errors.New`; parsed values are values.
- AS width comes from the record type, never sniffed (spec §4.2, §1 "Facts").
- Every public signature is in `api/mrt.txt` / `api/bgp.txt`; `MRT_API_UPDATE=1 go run ./internal/apisurface -check` rewrites them; `go run ./internal/apisurface -check` passes at every commit.
- The parser never panics on any input; a malformed record or attribute never ends the stream (spec §5.2).
- All work is local in `mrt`. Creating the GitHub repository, pushing, tagging and releasing wait for the user's explicit go-ahead.
- Heavy runs (real data, `internal/compare`) one at a time, alone, under `memguard.sh`, `GOMAXPROCS=4`.
- Every figure written into docs or the CHANGELOG comes from a command run in this work; anything not measured is called unknown.
- Commits on branch `v0.1` (created in Task 0), never on `main` after the first commit.

## Review Focus

1. **Several PEER_INDEX_TABLEs in one stream** (concatenated RIB files, `cat a.mrt b.mrt`): `Routes` must resolve each RIB entry against the most recent table, not the first. → Task 9, `TestRoutesUsesLatestPeerTable`.
2. **Empty or tiny inputs** (a zero-byte file, an empty gzip member, 11 bytes): `Records` yields nothing and no error for empty; one `ErrTruncated` for a partial header. → Task 6, `TestRecordsEmptyAndShort`; Task 9, `TestDecompressEmpty`.
3. **Withdraw-only and End-of-RIB UPDATEs** (no attributes at all; only MP_UNREACH): no diagnostics, withdrawals yielded, End-of-RIB yields nothing. → Task 5, `TestParseUpdateEndOfRIB`; Task 9, `TestRoutesWithdrawOnly`.
4. **IPv4 NLRI with an IPv6 next hop** (RFC 8950, in MP_REACH with AFI 1) and IPv4 prefixes carried in MP_REACH at all: decoded, `NextHop` is the IPv6 address. → Task 5, `TestMPReachIPv4WithIPv6NextHop`.
5. **Empty AS path and a path ending in an AS_SET** (collector-local iBGP, aggregates): `Origin()` false, `mrtdump` prints an empty path field / the set as bgpdump does. → Task 2, `TestASPathOrigin`; Task 11, `TestMrtdumpEmptyPath`.
