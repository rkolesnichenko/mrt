# mrt v0.3.1 DecompressWith Hardening Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Bound the parallel bzip2 reader's memory by `fixed + Workers × small`, make a cancel or stop start no queued job, and stop speculative decodes that cannot be used, with no exported change.

**Architecture:** `internal/bzip2` gains a speculative block decode with an output cap that returns no data when capped or past its input. The parallel reader's workers use it, dispatch waits on a 32 MiB budget of segment copies, and `stop()` keeps workers from starting queued jobs. Gates compare v0.3.0 and v0.3.1 in the same run.

**Tech Stack:** Go 1.23 floor, standard library only.

**Spec:** `docs/superpowers/specs/2026-10-21-mrt-v0.3.1-design.md` (amends `docs/superpowers/specs/2026-10-20-mrt-v0.3-design.md`).

## Global Constraints

- `api/` stays byte-identical: `go run ./internal/apisurface -check` passes with no `MRT_API_UPDATE`.
- No `net`, no `require` in root `go.mod`; Go 1.23 floor (CLAUDE.md principles 3, 4).
- Errors are values; never panic (principle 2).
- Output of `DecompressWith` is byte- and error-identical to `Decompress` on every input (spec §4).
- `Decoder.Block`, `Header`, `StreamEnd` and `NewReader` behave exactly as now; the copied standard code in `internal/bzip2/bzip2.go` is not edited (spec §5.1, §5.2).
- No RIS bytes in the repository (R18). Committed fixtures are synthetic.
- Every figure in a doc or the CHANGELOG comes from a command run in this work, with its log named under `.data/`.
- Heavy runs (real data, gates) run one at a time, alone, under `memguard.sh` (`~/DEV/rpsl/.superpowers/sdd/tools/memguard.sh`, with `MEMGUARD_NORMAL_PRIORITY=1` for timings), `GOMAXPROCS=4`.
- Tests that count goroutines or hook calls across goroutines are not parallel (v0.3 Ruling 3).
- `go test ./...` stays near a minute.

## Review Focus

1. A block that spans a whole 8 MiB segment at Workers 16, under the 32 MiB budget: dispatch never stalls and output is identical (Task 2, `TestDecompressWithBounds` input list).
2. A cancel while the chain is decoding a capped block serially: Read returns `context.Canceled` after that block and no goroutine is left (Task 2, `TestDecompressWithCancelDuringSerialBlock`).
3. A damaged capped block (flipped byte in the zero fixture): the same bytes and error as `Decompress` (Task 2, `TestDecompressWithCappedDamaged`).
4. Workers 1 with every block capped: identical output, no deadlock (Task 2, `TestDecompressWithBounds` at W1).
5. Real files at W14, where the budget and 28 outstanding interact: no slower than v0.3.0 (Task 3 speed gate).

### Task 1: Speculative block decode, zero fixtures, block-size measurement

**Files:**
- Modify: `internal/bzip2/block.go`
- Test: `internal/bzip2/bzip2_test.go`
- Create: `testdata/bzip2/zeros-1.bz2`, `testdata/bzip2/zeros-9.bz2`
- Modify: `testdata/README.md` (one line per fixture: the command that made it)
- Modify: `internal/decompbench/main.go` (a `-blocks` mode)

**Interfaces:**
- Produces: `var ErrOverCap = errors.New("bzip2: block output over the cap")`;
  `func (d *Decoder) SpeculativeBlock(br *BitReader, level, maxOut int) (data []byte, storedCRC uint32, err error)`.
  It is `Block`, except: if the block's output passes `maxOut` bytes it stops filling chunks and returns `nil, 0, ErrOverCap`; if `br.Err() != nil` once `readBlock` is done it returns `nil, 0, br.Err()` before producing output. Otherwise it returns what `Block` returns. In both early returns it makes no exact-size copy.
- Produces: `go run ./internal/decompbench -blocks FILE...` prints per file the block count, the largest and the mean decoded block size in bytes, and last a line `cap: N`: the smallest power of two at least twice the largest block over all files, and at least 2 MiB (spec §5.1).

### Task 2: Bounded speculation and a draining stop

**Files:**
- Modify: `decompress_bzip2.go`, `export_test.go`
- Test: `decompress_with_test.go`

**Interfaces:**
- Consumes: `bzip2.SpeculativeBlock`, `bzip2.ErrOverCap` (Task 1); the cap value Task 1's report names.
- Produces (in `decompress_bzip2.go`): constants `specCap` (Task 1's value) and `segmentBudget = 32 << 20`; `bzip2Hooks` gains `held func(segBytes int64, outstanding int)`, called in Read's goroutine after every dispatch, and `started func(bit uint64)`, called by a worker after it has taken a job and checked for stop, before it decodes (any goroutine; the hook must be safe for that).
- Produces (in `export_test.go`): `type Bzip2Hooks struct { Extra func(lo, hi uint64) []uint64; Discarded func(bit uint64); Took func(bit uint64, speculative bool); Held func(segBytes int64, outstanding int); Started func(bit uint64) }` and `func DecompressWithBzip2Hooks(r io.Reader, opts DecompressOptions, h Bzip2Hooks) (io.Reader, error)`; `DecompressWithHooks` stays, calling it.

- [ ] **Step 1: Write the failing tests** in `decompress_with_test.go` (not parallel):
  - `TestDecompressWithBounds`: inputs `zeros-1.bz2`, the bench file, `level1.bz2`, `multi-stream.bz2`, the end-magic flood of `TestDecompressWithEndMagicFlood`, a sparse block-magic input (`"BZh9"` then, to 32 MiB, the block magic's 6 bytes followed by 200 KiB of zeros, repeated), and a block spanning 8 MiB (as `internal/bzip2`'s `TestBlockSpanning8MiB` builds it); Workers 1, 3, 4 and 16 (under `RaceEnabled`, 1 and 4 only). For each: `checkSame` against `Decompress`; every `Held` call has `segBytes <= 32<<20` and `outstanding <= 2*workers`.
  - `TestDecompressWithCapsZeroBlocks`: `zeros-1.bz2` at W4: every `Took` call has `speculative == false`, 12 calls, output 60,000,000 zero bytes, error nil.
  - `TestDecompressWithCappedDamaged`: `zeros-1.bz2` with one byte flipped (xor 0x01) at each of 10 offsets from 4 to the end (5 under `RaceEnabled`), W4: `checkSame` against `Decompress`.
  - `TestDecompressWithCancelStartsNoJob`: the bench file at W2. `Started` counts starts and blocks the first 2 on a gate channel. Read with `io.ReadAll` in a goroutine; once 2 starts are seen, cancel, then close the gate. Expected: `ReadAll`'s error is `context.Canceled`, the start count is still 2, and `waitGoroutines(base) == base`.
  - `TestDecompressWithCancelDuringSerialBlock`: `zeros-1.bz2` at W4; cancel after the first 1 MiB of output; the next Read returns `context.Canceled` within 2 s and `waitGoroutines(base) == base`.

- [ ] **Step 2: Run** `go test -count=1 -run 'DecompressWith(Bounds|CapsZero|CappedDamaged|Cancel)' .`. Expected: FAIL (`DecompressWithBzip2Hooks` undefined).

- [ ] **Step 3: Implement** in `decompress_bzip2.go`:
  - Workers call `SpeculativeBlock(br, j.level, specCap)`; a result with an error of `ErrOverCap` or nil data from past the segment is not usable (as `whole == false`).
  - The reader keeps `segHeld int64`, the bytes of segment copies of outstanding jobs (added at dispatch, taken off when the chain receives or reaps the result). `dispatch` sends a job only if `segHeld + len(seg) <= segmentBudget`, or no job is outstanding; `pump` stops when dispatch is held by the budget, as it stops at 2 × Workers.
  - `stop()` closes a channel of its own before it closes `jobs`; a worker checks it and `ctx.Done()` without blocking before each job it takes, and returns if either is closed; `stop()` drains the jobs left in the queue.
  - Update the file's comments (the `pump` and `stop` docs, the bounds) to §5.3.

- [ ] **Step 4: Run** `go test -count=1 .`, then `env GOMAXPROCS=2 go test -race -count=20 -run 'DecompressWith' .` (output to a file, then `echo "exit=$?"`). Expected: PASS, exit 0.

- [ ] **Step 5: Run** `go test -count=1 ./...` and `go run ./internal/apisurface -check`. Expected: PASS, no API diff.
