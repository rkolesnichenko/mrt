# mrt v0.3.2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Close v0.3.1's open items:
- find the cause of the mrtcut gzip slowdown, and fix it if it is real;
- measure every term of the bzip2 bound;
- correct v0.3.1's two wrong statements;
- do the deferred test housekeeping.

There is no API change.

**Architecture:**
- **Housekeeping first.** Then a diagnosis whose log decides the mrtcut change.
- **Bound measurement.** New test hooks in the parallel bzip2 reader count each term. One shared builder of crafted bzip2 inputs (`internal/bzcraft`) serves the opt-in hook test and `decompbench -mem`.
- **Docs and the release checks last.**

**Tech Stack:** Go 1.23 module, standard library only. The system `bzip2` (1.0.8) builds the crafted inputs at run time, as `decompress_with_test.go:141` already does.

**Spec:** `docs/superpowers/specs/2026-10-21-mrt-v0.3.2-design.md`. It amends `docs/superpowers/specs/2026-10-21-mrt-v0.3.1-design.md`.

## Global Constraints

- `api/` stays byte-identical: `go run ./internal/apisurface -check` passes with no `MRT_API_UPDATE`.
- No `net`, no `require` in root `go.mod`; Go 1.23 floor; errors are values, never panic (CLAUDE.md principles 2-4).
- Output of `Decompress` and `DecompressWith` is byte- and error-identical on every input (spec §4).
- `Decompress` is not changed (spec §3).
- No RIS bytes in the repository (R18). `.data/realdata/rrc00-*` is read only. Committed fixtures are synthetic; `testdata/` stays under 15 MB.
- Every figure in a doc or the CHANGELOG comes from a command run in this work, with its log named under `.data/`.
- **Heavy runs:** real data, gates, series and profiles run one at a time, alone, under `memguard.sh` (`~/DEV/rpsl/.superpowers/sdd/tools/memguard.sh`), with `GOMAXPROCS=4` and `MEMGUARD_NORMAL_PRIORITY=1` for timings.
- Tests that count goroutines or hook calls across goroutines are not parallel.
- `go test ./...` stays near a minute.
- **Decision thresholds (spec §5.1):** under 3% slower, no change. A readahead fix must bring every slower tool within 3% of v0.2.1, slow the v0.3 gzip gate by no more than 5%, and keep the 256 KiB queue bound.
- **Bound pass rule (spec §5.2), fixed before any run:** each counted term's peak is at or under its bound, and the GOGC=10 heap peak growth is under the total bound (216.7 MB at W4, 389.0 MB at W14). Over is a failure: no new method afterwards.

## Review Focus

1. **Hooks off by default.** With no hooks set, the new counting costs nothing and changes no behaviour. The v0.3.1 speed gate (Task 5) and `TestDecompressWithMatchesDecompress` cover this; Task 4 adds `TestDecompressWithNoHooksNoCount`.
2. **The results counter across goroutines.** Workers add and the chain subtracts. A miscount would make the gate meaningless. Task 4's unit test checks that the counter never goes negative and returns to 0 at EOF on the bench file, and `-race -count=5` runs it.
3. **A cancel during the new crafted inputs.** It leaves no goroutine, as on every other input. Task 4 adds the crafted inputs to `TestDecompressWithCancelStartsNoJob`'s goroutine check.
4. **The fixture move.** No test silently loses an input after the glob change. Task 1 asserts the glob counts: 3 files in `testdata/bzip2/*.bz2`, 2 in `testdata/bzip2/zeros/`.
5. **mrtcut's gzip fallback, if Task 3 takes it.** Output is identical for gzip, bzip2, plain and stdin inputs. Task 3 runs the existing `TestCount`, `TestCutStdin` and `TestCutFirstAndAlso` on a gzip copy of the fixture.

**Interfaces:**
- Produces, in `internal/bzcraft`:
  - `func EndMagicFlood(workers int) []byte`
  - `func SparseBlockMagics() []byte`
  - `func ResultsLoad() ([]byte, error)`: one block over the 2 MiB cap, then blocks each decoding to just under 2 MiB.
  - `func SegmentLoad() ([]byte, error)`: blocks with compressed segments as large as the reader's window allows.
  - `func UnderCapBlocks() ([]byte, error)`: blocks under the cap, so workers make exact-size copies.

  The three new builders compress generated plaintext with the system `bzip2` (`exec.Command("bzip2", "-9", "-c")`). They return an error if `bzip2` is missing; callers skip. Each output is under 15 MB, and none is committed.
- Produces, in package mrt:
  - `bzip2Hooks.results func(held int64)`: called with the bytes of results that workers have sent and the chain has not yet received or reaped, after every change, from any goroutine.
  - `bzip2Hooks.window func(bytes int)`: called with `len(z.win)` after every `fill` and `compact`, from Read's goroutine.
  - With no hooks set, nothing is counted.
  - `Bzip2Hooks.Results` and `Bzip2Hooks.Window` expose them.

- [ ] **Step 1: Write the failing unit tests** in `decompress_with_test.go`, not parallel:
  - `TestDecompressWithResultsCounted`, on the bench file at W4, through `DecompressWithBzip2Hooks` with `Results` set:
    - at least one call has `held > 0`;
    - every `held >= 0`;
    - the last call's `held == 0` after EOF.

    After `stop` the count is not kept: results a worker sent that nobody receives are dropped with the reader, and the hook is not called again.
  - `TestDecompressWithWindowCounted`: `Window` is called; every value is at most `2 × (8 MiB + 2 × Workers MiB)`.
  - `TestDecompressWithNoHooksNoCount`: through an `export_test.go` helper `CountsResults(r io.Reader) bool`, a reader from `DecompressWith` with no hooks has no results counter; one with `Results` set has one.

  Run them: compile failure, then FAIL.

  - `window` is called in `fill` and `compact`.

  Run Step 1's tests: PASS. Run `go test -race -count=5 -run 'TestDecompressWith(ResultsCounted|WindowCounted)$' .`: PASS.
