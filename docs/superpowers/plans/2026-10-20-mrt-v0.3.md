# mrt v0.3 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add an opt-in `DecompressWith` that decompresses bzip2 in parallel and runs gzip ahead of the reader, with output identical to `Decompress` on every input.

**Architecture:**
- `internal/bzip2` is a copy of Go 1.27.2's `compress/bzip2` that can decode one block from a bit offset and say where it ended.
- The root package's bzip2 reader decodes serially along the chain of exact block ends, and uses workers only to decode candidate blocks ahead.
- gzip gets one readahead goroutine with a 256 KiB queue.
- `Decompress` is untouched.

**Tech Stack:** Go 1.23 floor (developed on 1.27.2), standard library only.

**Spec:** `docs/superpowers/specs/2026-10-20-mrt-v0.3-design.md` (approved by the user 2026-10-20, including the copy of `compress/bzip2`).

## Global Constraints

- Root `go.mod`: `go 1.23`, no `require`. No `net` import (`go list -deps ./... | grep -x net` prints nothing).
- `Decompress(r io.Reader) (io.Reader, error)` keeps its behaviour and code. No other exported signature changes. `api/mrt.txt` gains only `DecompressOptions` and `DecompressWith`.
- C1: `DecompressWith(r io.Reader, opts DecompressOptions) (io.Reader, error)` returns what `Decompress` returns, and `go run ./internal/apisurface -check` passes.
- Equivalence (spec §6.4): for any input and any `Workers ≥ 1`, reading `DecompressWith` to the end gives the bytes `Decompress` gives. Either both succeed, or both fail after the same bytes. Error text may differ.
- `Workers > 0` with a nil `Context` is an error, and so is `Workers < 0`. Both are unexported `errors.New` values.
- **Bounds (spec §6.2, §6.3):**
  - at most `2 × Workers` candidates speculated ahead;
  - a speculative segment holds at most 8 MiB of compressed input;
  - decoded blocks go into growing buffers, never preallocated from input;
  - the gzip readahead queue holds at most 256 KiB of decompressed output.
- For bzip2, no goroutine reads the caller's `r`. A `Read` that returns EOF or an error first waits for every worker to exit.
- `internal/bzip2` carries Go's LICENSE text (`internal/bzip2/LICENSE`) and a header note in each copied file naming its source (`compress/bzip2`, Go 1.27.2). The standard code paths stay as they are.
- Every figure in the CHANGELOG comes from a command run in this work, with its log in `.data/` named. Heavy runs go one at a time, alone, with `GOMAXPROCS=4` and a `GOMEMLIMIT`, at normal priority.
- `internal/compare` and `TestRealData`'s existing subtests stay on `Decompress`.
- Commits go on branch `release-0.3.0` only. No push.
- The spec's "Task 1 is the gate" is split here. The bzip2 gate runs at the end of Task 2 and the gzip gate at the end of Task 3, the first points where each reader exists. Nothing is built on a reader before its gate passes.

## Review Focus

1. **A caller that stops early.** It reads a few records through `Records`, breaks, then cancels. Every goroutine must end, with none left reading. Task 2 tests it.
2. **A slow or blocking input**, such as a pipe or `mrtdump -` on stdin. bzip2 must not start a goroutine on `r`, and its output must stay identical. Task 2 tests it with an `io.Pipe` fed slowly.
3. **An input reader with odd behaviour.** That means 1-byte reads, data returned together with an error, or an error mid-file. The output must be the same bytes and then an error, as `Decompress` gives. Tasks 2 and 3 test it with `testing/iotest`.
4. **A caller reading with tiny buffers** (`p` of 1 byte). The output must be correct. Tasks 2 and 3 run `iotest.TestReader`-style 1-byte reads.
5. **Odd worker counts.** That means more workers than blocks (8 workers, a one-block file), `Workers = 1`, and `Workers < 0`. The first two must give identical output; `Workers < 0` is an error. Task 2 tests them.

**Interfaces:**
- Produces, all in `package bzip2` (internal):
  - `func NewReader(r io.Reader) io.Reader`: the serial reader, with the standard reader's behaviour.
  - `type BitReader`: the copy's bit reader, with `NewBitReader(r io.ByteReader) *BitReader`, `Offset() uint64` (bits consumed since construction) and `Err() error`.
  - `type Decoder struct{…}`, which keeps its `[]uint32` block buffer between calls.
  - `func (d *Decoder) Block(br *BitReader, level int) (data []byte, storedCRC uint32, err error)`:
    - `br` is positioned at a block magic. `Block` reads the magic and the block.
    - It returns the block's bytes, its stored CRC, and the error the standard reader would give for this block.
    - On a CRC mismatch it returns the bytes and the error together, as the standard reader emits them.
    - After the call, `br.Offset()` is the block's end.
  - `const BlockMagic, EndMagic uint64 = 0x314159265359, 0x177245385090`.
  - `func FoldCRC(stream, block uint32) uint32`, which is `(stream<<1 | stream>>31) ^ block`.
- `NewReader` must be built on `Decoder.Block`, `BitReader` and `FoldCRC`. It is then the same serial path Task 2 uses, and it reproduces the standard handling after an end magic (spec §6.2: EOF, one byte then EOF, `BZh` + level).

### Task 2: `DecompressWith` for bzip2 — the parallel reader, and the bzip2 gate

**Files:**
- Modify: `decompress.go`, adding `DecompressOptions`, `DecompressWith` and the two errors. `Decompress` stays byte-for-byte.
- Create: `decompress_bzip2.go` (the parallel reader), `decompress_with_test.go`, and an export_test hook `export_test.go` for injecting candidates.
- Create: `internal/decompbench/main.go`, the gate tool.
- Modify: `fuzz_test.go` (`FuzzDecompress`), `scripts/fuzz.sh`, `api/mrt.txt` (`MRT_API_UPDATE=1`).

**Interfaces:**
- Consumes: Task 1's `Decoder.Block`, `NewBitReader`, `BitReader.Offset`, `BitReader.Err`, `FoldCRC`, `BlockMagic`, `EndMagic`.
- Produces: `type DecompressOptions struct { Workers int; Context context.Context }` and `func DecompressWith(r io.Reader, opts DecompressOptions) (io.Reader, error)`, both with spec §6.1's doc comments.
- In this task, gzip with `Workers > 0` is read as `Decompress` reads it. Task 3 adds readahead.
- **The reader** (spec §6.2):
  - The caller's `Read` reads `r` into a window and scans it for `BlockMagic` at bit granularity. Every match is a candidate.
  - Candidates go to `Workers` goroutines (at most `2 × Workers` outstanding). Each decodes a copy of at most 8 MiB from the candidate, with the stream level in force at that position.
  - The ordered reader keeps the chain:
    - The first block of a stream is at the stream header's offset + 32 bits.
    - After a block, the next block starts at its end.
  - **Speculative results.** A speculative result is used only if it started exactly at the chain's position, used the chain's level, and did not reach the end of its segment (`Err()` is nil after `Block`). Otherwise the chain decodes that block serially from the window with `Block`, growing the window from `r` as it reads.
  - **Stream ends.** At an `EndMagic` the chain checks the folded CRC. It then handles what follows as Task 1's `NewReader` does.
  - **The test hook** lets a test add false candidates to the scan.
- **The gate tool** `internal/decompbench`:
  - Usage: `decompbench -workers N FILE...`.
  - It prints, for each file:
    - `Decompress` decompress-only time and MB/s;
    - `DecompressWith` decompress-only time, MB/s and the speed-up;
    - the SHA-256 of both outputs and whether they are identical;
    - `Decompress`+`Routes` and `DecompressWith`+`Routes` times and that speed-up.
  - It also prints Go version, GOMAXPROCS, NumCPU and GOMEMLIMIT on its first line.
