# mrt v0.2: routes a reconciliation library can hold

Status: implemented · 2026-10-20 · branch `release-0.2.0`, release v0.2.0

This design amends `2026-10-16-mrt-design.md` (the v0.1 design) where it says
so. CLAUDE.md's principles and rulings hold unless a section below names the
ruling it changes.

## 1. Intent

The first consumer of v0.2 is the IRR-vs-BGP reconciliation library (a
separate module that imports `mrt` and `rpsl`). A reconciliation run, as the
user describes it:

- loads **a full RIB per collector** and **holds it in memory**: three RIBs
  per run, RIS rrc00's bview, route-views2's and route-views6's (user's
  decision),
- then applies that collector's **update files** on top,
- and judges the resulting table against IRR policy.

The user decided the split: **the reconciliation library keeps the table;
`mrt` hands over routes.** So `mrt` v0.2 must hand over everything the table
keeper needs, in stream order, and make held routes cheap. The user's memory
budget for one run, the three RIBs loaded, is **about 8 GB**, and the user
decided that `mrt` **shares identical paths and communities** between routes
to fit it.

## 2. Goals

1. **Peer-state events in `Routes`** (user's decision): a BGP4MP state change
   reaches the table keeper in stream order, between the announcements and
   withdrawals around it, so it can drop a peer's routes when its session
   goes down. `mrt` reports the event; the table keeper decides what it means.
2. **`Route.Originated`**: the RIB entry's originated time, which `Routes`
   drops today.
3. **Held routes do not hold record bytes.** A `Path` that a caller keeps
   must not keep its MRT record's buffer alive.
4. **Sharing** (user's decision): identical decoded paths, and identical AS
   paths and community lists inside paths that differ, are one value in
   memory.
5. **Exported diagnostic codes** (user's decision): callers compare against
   constants, not string literals.
6. **Typed extended communities** (user's decision; uses proposed by me and
   accepted): readable in reports and usable in filters.

## 3. Non-goals

- Keeping the table, applying updates, or deciding what a state change means
  (the reconciliation library's job, user's decision).
- A pluggable decompression hook and a buffer-reuse mode (left out of v0.2 by
  the user; the reuse mode contradicts holding routes).
- BMP, RIS Live, MRT writing, RIB reconstruction, ASPA, RPKI.
- Interpreting every extended community type (only those in §4.5).

## 4. Anti-goals (a failure even if it works)

- A shared path that differs, in any field or diagnostic, from what a fresh
  decode of that route's bytes gives.
- A silent change for existing callers of `Routes(records)`: it keeps
  yielding exactly the routes it yields today, plus `Originated`. The
  deliberate exceptions are the R20 amendment (§6.4) and the compact `Path`
  API (§6.4a), both listed in the CHANGELOG.
- Weakening lossless `Raw`, adding a dependency, importing `net`, raising the
  Go 1.23 floor, or reading AS width from bytes.
- Losing an extended community's bytes: the raw 8 bytes stay the source of
  truth, junk types included (the 2026-10-19 census saw types 0x1A/0x70,
  0x00/0x43, 0x97/0xC7 in the wild).

## 5. Facts this design rests on (measured 2026-10-16 and 2026-10-20)

- Routes in the three RIBs of the real-data run (CHANGELOG 0.1.0, lines
  compared, one line per entry): RIS rrc00 bview 55,579,615; route-views2
  17,454,476; route-views6 4,702,913. **77,737,004 in total.**
- `unsafe.Sizeof`: `bgp.Path` 328 bytes (a 352-byte heap object), `mrt.Route`
  168, `bgp.MPReach` 112 (Go 1.27.2, darwin/arm64).
- Duplication: potaroo full tables (2026-10-20) have 278,446 unique AS paths
  in 3,230,450 IPv4 entries (8.6%) and 150,526 in 1,004,156 IPv6 (15.0%). The
  route-views2 fixture slice has 2,768 unique (peer, attribute bytes) sets in
  31,782 routes. Full-RIB ratios for (peer, attributes) are **unknown**.
- Every route-views6 RIB route's `Path` aliases its record today: R20 keeps
  the full-form MP_REACH NLRI in `RawNLRI` (24,870 of 24,870 fixture routes).
- bgpkit-parser 0.22.0's JSON lists extended communities in `communities` as
  objects: `TransitiveTwoOctetAs {global_admin, local_admin, subtype}`,
  `TransitiveFourOctetAs`, `TransitiveOpaque {subtype, value}` (Color is
  subtype 11), and `Raw` (8 bytes) for types it does not know. Seen on
  `testdata/mrt/rv2-updates-et.20261015.1200.gz`.
- Extended communities seen in 8 RIS and RouteViews update files of
  2026-10-19 (most frequent first): route target and route origin (2-octet
  AS, then 4-octet AS, then IPv4), Color (3,11), link bandwidth (0,4),
  Encapsulation (3,12), EVPN router MAC (6,3), flowspec redirect (128,8).
  No RFC 8097 communities.

**Consequence for the budget** (an estimate, not a measurement): at 77.7
million routes, the table keeper's own per-route entry dominates (at 40
bytes, about 3.1 GB), and shared paths add roughly the number of distinct
(peer, attributes) sets times about 450 bytes (path plus slices). If that
number is 10% of routes, paths take about 3.5 GB, and the run is near 8 GB
with rrc00 included. Hence §6 step 1.

## 6. The design

### 6.1 Order of work

1. **Measure first.** Before the API is fixed, a throwaway measurement
   (outside the module's public API) loads the three full RIBs, shares paths
   by (peer-independent) attribute bytes, and reports: distinct paths,
   distinct AS paths, distinct community lists, blocks with only Info
   diagnostics, and retained heap for the shared paths and, separately, for
   the interner's own index. Log under `.data/`. The go/no-go counts both
   (everything `mrt` retains). If they exceed about 4 GB, stop and bring the figures to the user before building §6.4
   as written; a more compact `Path` layout (an API break, allowed pre-v1)
   would then be on the table.
2. Then §6.2–§6.6, each with tests first.

### 6.2 Peer-state events

- `Routes(records)` is unchanged in what it yields. A new
  `RoutesWith(records, RoutesOptions)` (convention C1) takes the options;
  `Routes` is `RoutesWith` with the zero options. (My call: opt-in, so that
  `Routes` keeps meaning "one route per peer, prefix and path ID".)
- `RoutesOptions.PeerStates bool`: when true, each BGP4MP and BGP4MP_ET state
  change record (subtypes 0 and 5) yields one `Route` with
  `Kind == KindPeerState` (value 4), `Time` (with microseconds for _ET),
  `Peer{Addr: PeerAddr, AS: PeerAS}`, and two new fields, `OldState` and
  `NewState` (type `mrt.State`). Prefix, family and path ID are zero, `Path`
  is nil, `Diagnostics` nil. `Kind.String()` returns `"S"` (my call).
- Stream order is record order. Within one UPDATE, withdrawals come before
  announcements, as now.
- Peer identity for BGP4MP is address plus AS (BGP4MP carries no BGP ID); the
  table keeper matches RIB peers (which carry a BGP ID) by the same pair.

### 6.3 `Route.Originated`

`Originated time.Time`: the RIB entry's originated time for TABLE_DUMP_V2,
the record's originated time for TABLE_DUMP, zero for UPDATE and peer-state
routes.

### 6.4 Held paths and sharing

- **R20 amended (user's decision, always, not only with an interner):** in a
  RIB entry, the full
  RFC 4760 form of MP_REACH_NLRI keeps its family and next hops, and its NLRI
  is **not** kept (`RawNLRI` nil): the record supplies the prefix, and the
  bytes stay reachable through `Attrs.Raw()`. This removes the alias that
  makes route-views6 paths hold their records, and makes such paths
  shareable across prefixes. Outside a RIB, nothing changes. CLAUDE.md's
  R20 line and the v0.1 design's §4.2 are updated with the code.
- **`bgp.Path.Clone() Path`**: a deep copy that shares no memory with the
  attribute block or the original (slices, `MPReach`, `MPUnreach`, `Unknown`
  values).
- **`bgp.Interner`** (in `bgp`, so a later BMP reader can use it):
  `bgp.NewInterner() *Interner`, safe for concurrent use (one interner may
  serve every collector of a run, loaded in parallel). It grows until the
  caller drops it; no eviction in v0.2.
  - Whole paths: decoding an attribute block through the interner returns a
    shared `*Path` and its diagnostics when an equal block was decoded
    before in the same `Context`. "Equal" ignores what decoding does not
    read: the RIB-entry MP_REACH NLRI above. Every interned path is a
    `Clone`, so it holds no record bytes.
  - Inside paths that differ: equal AS paths (received, AS4 and merged) and
    equal community, extended community and large community lists share
    their backing arrays.
  - **Invariant:** for every route, decoding with and without an interner
    gives deeply equal `Path` and `Diagnostics`. Tested over every fixture
    and in a fuzz target; this is the anti-goal of §4 made a test.
  - A block with a Warning or Error diagnostic is decoded fresh, not
    interned. A block whose diagnostics are all Info (for example
    `bgp/as4path-ignored`, emitted on every 4-byte-AS block that carries
    AS4_PATH) is interned keyed on its exact bytes, with no NLRI exemption,
    so its diagnostics' offsets match a fresh decode. (My call; the §6.1
    measurement counts such blocks.)
  - **UPDATE paths are not interned whole** (my call): outside a RIB,
    `MPReach.NLRI` and `MPUnreach.Withdrawn` are the UPDATE's own prefixes,
    so nearly every UPDATE block is unique and would only grow the interner.
    An UPDATE route's path shares its AS paths and community lists through
    the interner, and is a `Clone`, so it holds no record bytes.
  - With an interner in use, every path handed out holds no record bytes:
    interned paths and freshly decoded ones are both clones.
- **Entry point (user's decision):** `func (in *Interner) Decode(a Attrs)
  (*Path, []Diagnostic)`. It returns a shared pointer, a deliberate exception
  to "parsed values are values": sharing is the interner's purpose, and
  `Route.Path` is already a `*bgp.Path`. `Attrs.Decode` is unchanged. (An
  `Attrs.DecodeWith` with an interner option is ruled out: C1 requires it to
  return what `Decode` returns, a value.) The exception is noted in the v0.1
  design's §3.
- **Wiring:** `RoutesOptions.Interner *bgp.Interner`; nil means today's
  behaviour (a fresh `Path` per entry or UPDATE, which may alias record bytes
  only in `Unknown` values and the non-RIB `RawNLRI`, as documented).

### 6.4a Compact `Path` (user's decision 2026-10-20, after the §6.1 gate)

The §6.1 measurement (log `.data/heldsize-prototype-r2.log`; 2026-10-20 RIBs
of rrc00, route-views2 and route-views6) found 77,853,052 routes, 12,809,618
distinct paths, and 8,110,280,352 live bytes retained by `mrt` with sharing:
`Path` structs 4,508,985,536 (352-byte objects), the whole-path index
1,527,034,336, shared parts and their indexes the rest. The gate tripped; the
user chose: **a compact `Path`, and dropping the whole-path index after the
RIBs are loaded.**

- `Path` keeps as exported fields only what most paths carry: `ASPath`,
  `Communities`, `LargeCommunities`, `MPReach`, `MED`/`HasMED`,
  `LocalPref`/`HasLocalPref`, `Origin`/`HasOrigin`, `AtomicAggregate`,
  `OnlyToCustomer`/`HasOnlyToCustomer` (OTC is on 3-21% of UPDATEs).
- NEXT_HOP is held as its 4 bytes and read through `NextHop() netip.Addr`
  (zero when absent). (My call: NEXT_HOP is IPv4 by RFC 4271; this keeps
  `Path` at 112 bytes on 64-bit platforms, a 112-byte allocation, instead of
  144.)
- Everything else moves behind one unexported pointer, nil when the path has
  none of it, read through methods: `ReceivedASPath() ASPath` (equal to
  `ASPath` unless AS4_PATH was merged; stored only then), `AS4Path() ASPath`,
  `Aggregator() (Aggregator, bool)`, `ExtCommunities() []ExtCommunity`,
  `OriginatorID() netip.Addr`, `ClusterList() []netip.Addr`,
  `MPUnreach() *MPUnreach`, `Unknown() []Attribute`.
- `Path` is now produced only by decoding (its rare part cannot be set from
  outside the package); `Clone` copies the rare part too.
- `(*Interner).DropPathIndex()`: forgets the whole-path index; paths already
  handed out are unaffected, and component sharing (AS paths, community
  lists) goes on. A run calls it after loading its RIBs (UPDATE paths are
  not shared whole anyway).
- **Gate, re-stated:** after loading the three RIBs through `RoutesWith` with
  an interner and calling `DropPathIndex`, the live bytes `mrt` retains
  (HeapAlloc) are at most 4 GB. My estimate: about 3.1 GB. If above, stop
  and bring the figures to the user.

### 6.5 Typed extended communities

- `ExtCommunity` stays `[8]byte`. New methods: `Type() uint8`,
  `Subtype() uint8`, `Transitive() bool`, and accessors that report `ok`
  false for other types:
  - route target and route origin in the two-octet AS (type 0x00, 0x40),
    IPv4 (0x01, 0x41) and four-octet AS (0x02, 0x42) forms, subtypes 2 and 3:
    global administrator (ASN or IPv4) and local administrator;
  - Color (0x03, subtype 0x0B): color value;
  - link bandwidth (0x00/0x40, subtype 0x04): AS and float32 bandwidth;
  - Encapsulation (0x03, subtype 0x0C): tunnel type;
  - RFC 8097 origin validation state (0x43, subtype 0x00): valid, not found,
    invalid;
  - flowspec redirect (0x80, subtype 0x08) is kept as type and subtype only
    (my call; flowspec routes never reach `Routes`).
- `String()`: labeled and unambiguous, e.g. `rt:64500:100`, `ro:64500:100`,
  `rt:192.0.2.1:100`, `color:100`; anything else prints its type, subtype and
  remaining six bytes in hex. The exact label set is the builder's, written
  down in the doc comment and pinned by tests.
- **Oracle:** the bgpkit golden normalizer (`internal/oracle`) starts
  comparing extended communities field by field where bgpkit-parser's JSON
  carries them (§5); that changes `testdata/golden/*.bgpkit.json`, which is
  re-recorded from the live oracle, never hand-edited, and reviewed as a
  diff. Divergences, if any, go into `divergences.md`.

### 6.6 Exported diagnostic codes

Every `Diagnostic.Code` value becomes an exported constant in `bgp` (today:
`bgp/attr-length`, `attr-value`, `nlri-length`, `as4path-ignored`,
`attr-duplicate`, `message-truncated`, `update-length`, `aspath-width`,
`message-header`, `attr-truncated`, `prefix-bits`, `nlri-family`,
`not-update`). The string values do not change. A test fails if code under
`bgp/` builds a `Diagnostic` with a code that is not one of the constants.
Naming is the builder's within C3 (for example `bgp.DiagAttrLength`).

## 7. Tests and gates

- Every new behaviour test-first; the existing suites, goldens and
  `TestLossless` unchanged except as §6.4 (R20) and §6.5 (oracle) say.
- `api/*.txt` regenerated with `MRT_API_UPDATE=1`; its diff is the API change
  list and goes in the CHANGELOG.
- The interner invariant (§6.4) over every fixture, and a fuzz target (or an
  extension of `FuzzRoutes`) decoding each input with and without one.
- Peer-state events over `testdata/synthetic/state-changes.mrt`, which
  already puts an UPDATE (second 5) between state changes, so it also pins
  their order against the routes around them (the RouteViews update fixtures
  contain no state changes).
- The measurement of §6.1, and at the end the same figures with the real
  API: retained heap of shared paths for the three RIBs, distinct counts, and
  the `internal/compare` gate (allocates less than gobgp) still passing.
- `scripts/check.sh` with `FUZZTIME=15s` ends `check: ok`; an independent
  reviewer reads the whole diff before merge.

## 8. Left to the builder

- Interner internals (key encoding, locking, sharding), as long as §6.4's
  invariant and concurrency hold.
- Constant names (C3), extended community accessor names and `String()`
  labels.
- How `mrtdump` is affected by the R20 amendment (it should not be: it does
  not print `RawNLRI`; confirm with the goldens).
